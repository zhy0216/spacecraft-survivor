# 武器星级发射差异与两星机炮命中调查

更新日期：2026-08-14

本文只讨论六种基础武器的 1★、2★、3★。合成武器由三把同型 2★ 合成后直接成为独立的 3★ 武器，没有自己的 1★/2★ 阶段，因此不放进逐星对照表。

## 结论：两星机炮漏弹的主因不是碰撞圆

直射弹当前使用“弹丸圆与敌人圆相交”的命中判定：

```text
弹丸中心与敌人中心的距离 <= 弹丸半径 + 敌人半径
```

自动机炮弹丸半径是 3 px，最小敌人蜂群蛭的半径是 7 px，合并命中半径是 10 px。机炮弹速 420 px/s，在 60 Hz 逻辑帧下每帧前进 7 px，小于最小命中圆直径 20 px；按当前默认弹速、敌速和体型，逐帧碰撞不是这次漏弹的主要原因。

真正的问题在两星双管的发射角：

- 2★ 自动机炮每次发射两颗真实弹丸。
- 两颗弹不是平行射出，也不会汇聚到已选目标，而是以炮口朝向为中心向左右各偏 3°。
- 2★ 射程约 418.95 px。在这个距离上，每颗弹相对目标中心线的横向偏移约为 `418.95 × sin(3°) = 21.9 px`。
- 21.9 px 已经大于蜂群蛭的 10 px 合并命中半径，所以目标即使静止、炮口正对其中心，两颗弹也可能从身体两侧同时掠过。
- 对蜂群蛭而言，目标距离超过约 `10 / sin(3°) = 191 px` 后，就开始存在这种“双弹夹空”的确定性几何风险。

移动目标还会放大问题：当前直射弹瞄准目标的现位置，不计算提前量。但这会影响所有实体弹武器；“升到 2★ 后突然更容易漏”主要仍是双管角度扇开的结果。

### 建议修正

2★ 机炮应保留“双管齐射”，但升级不能降低对单体目标的命中可靠性：

1. 两个炮口在瞄准线法向上分别偏移少量位置，例如 ±3 px。
2. 两颗弹平行沿瞄准方向发射，或分别从两个炮口汇聚到本次选中的目标点。
3. 不再把 `aimTolDeg` 同时当作双管散布角。它的本职是“炮管允许在多大误差内开火”，不是武器散布。
4. 增加回归测试：2★ 机炮正对 2★ 最大射程处的静止蜂群蛭时，两颗弹都应命中；至少不能出现升级后两颗全部固定打空。

如果未来把弹速或敌速提高到“一帧相对位移大于最小合并命中圆直径”，再把直射弹升级为线段扫掠碰撞。当前默认数值还没有到必须为这次问题引入扫掠判定的程度。

## 当前星级换算规则

现在的星级沿用旧等级数值档：

| 星级 | 实际使用的旧等级档 | 含义 |
| --- | ---: | --- |
| 1★ | Lv1 | 基础数值与基础发射方式 |
| 2★ | Lv3 | 数值跨两级成长；只有少数武器发生机制变化 |
| 3★ | Lv5 | 数值再跨两级成长；自动机炮获得穿透 |

当前所有武器都会随星级提高伤害和射程，并按各自体系提高射速、弹夹、热容量、充能速度或链数。但“每一星的发射形态都不同”目前并没有完整实现。

## 建议的逐星发射规范

目标不是让高星武器单纯“更花”，而是让玩家在一个开火周期内，不看 UI 也能辨认星级。建议遵守四条约束：

1. 升星不得降低命中可靠性。
2. 发射形态必须确定性，不引入随机散布。
3. 如果只是表现升级，不额外增加伤害结算次数；如果增加真实弹丸，必须同步定义单弹伤害和资源消耗。
4. 基础武器不能抢走合成武器的核心签名，例如基础迫击炮不做真实三连发、基础激光不做真实穿透。

### 星级视觉强度规范

星级差异不应只靠“多画几个粒子”。玩家真正能感知的是轮廓、节奏、运动方向和余波时间同时升级：

| 维度 | 1★ | 2★ | 3★ |
| --- | --- | --- | --- |
| 第一眼轮廓 | 单芯、单线、单环 | 双炮口、双股、双层或更长链 | 白亮能量核心 + 武器色大轮廓 + 专属几何符号 |
| 时间结构 | 开火即结束 | 主效果后增加短残影 | “蓄势/压缩 → 主爆发 → 余波”三段式 |
| 次级运动 | 无或很少 | 侧向粒子、螺旋尾迹、第二圈冲击波 | 向中心吸入与向外爆发同时存在，形成明显反差 |
| 命中反馈 | 小火花 | 火花 + 小环或短碎片 | 入口闪光、冲击环、碎片/电丝和持续余辉组合 |
| 屏幕反馈 | 无 | 极轻炮口后坐 | 只给低频重武器震屏；高频武器靠节奏和尾迹表达力量 |
| 建议存续 | 0.08–0.15s | 0.15–0.25s | 主闪 1–2 帧，余波 0.25–0.55s |

3★ 的重点是“有一个瞬间非常亮、随后留下有方向的余波”，而不是让全部粒子长期保持高亮。峰值和安静段形成反差，才会显得有重量。

#### 3★ 通用三段式模板

1. **蓄势或压缩**：能量点向炮口、弹体或命中点收缩。充能武器可持续 80–140ms；高射速武器不延迟开火，只在同一帧画一个快速收紧的压缩环。
2. **主爆发**：1–2 帧冷白核心，外层使用武器自身冷色。核心必须是全效果最亮、最干净的部分。
3. **余波**：冲击环、残影、碎片、电丝或烟迹沿武器作用方向运动 0.25–0.55s。余波先删也不能影响玩家看清真实弹道和命中范围。

战斗中的金色应继续只用于星级徽记和升星仪式，不进入常态弹道主体，避免与残骸、货币和暖色敌方读数混淆。常态 3★ 使用“冷白核心 + 塔型冷色光晕”即可获得足够亮度层级。

### 推荐的逐武器发射与粒子方案

以下方案优先改变表现，不改变现有伤害次数、资源消耗和合成武器签名。

#### 自动机炮

| 星级 | 发射形态 | 粒子与命中反馈 |
| --- | --- | --- |
| 1★ | 中线单发 | 短炮口闪、短弹尾、小型十字命中火花 |

| 3★ | 单条真实判定线，视觉表现为真空压缩后撕开整条航线 | 最后 100–140ms 充能阶段粒子向炮口倒吸；开火帧出现全屏可读的冷白主芯、两条外侧冲击轨和炮口后坐环；沿线敌人各出现薄环；光柱消失后保留 0.35–0.5s 空间裂痕残影 |

磁轨炮应是基础武器里最震撼的一种 3★ 演出，因为它本身低频、远程、单次伤害最高，有足够安静时间承载大效果：

- 开火瞬间建议震屏 5–7 px、持续 80–120ms。
- 可选 35–50ms 极短顿帧，但必须服从现有顿帧设置开关。
- 余波应比主光柱暗很多，不能长期遮挡敌人和射界。
- 实际判定仍只有当前 `lanceWidth`，外侧冲击轨只是视觉，不能暗示更宽的伤害范围。

3★ 迫击炮应是基础武器里空间占比最大的爆炸，但不能改写真实 90 px 爆炸边界：

- 实心伤害盘始终严格画在真实 AoE 半径内。
- 外侧冲击环可以超过伤害范围，但必须更薄、更透明，明确表示“余波而非伤害”。
- 建议震屏 3–5 px、持续 100–140ms；不需要顿帧，以免多颗迫击炮连续落地时把游戏锁成断续画面。
- 三颗围绕主弹的微光只是弹体结构，不能变成三次真实爆炸，避免抢走焦土骤雨的三连发签名。

### 3★ 升星瞬间的专属仪式

3★ 不只要在之后开火时更强，升到 3★ 的当下也应成为一局里的小高潮。建议把现有升级爆发扩成 0.7–0.9s 的四阶段效果：

| 阶段 | 时间 | 通用表现 |
| --- | ---: | --- |
| 能量抽离 | 0–120ms | 周围星尘和小粒子向武器硬点快速收缩，环境短暂变暗 |
| 核心点燃 | 120–220ms | 冷白核心闪光 + 3★ 星形轮廓，武器贴图快速放大后回弹 |
| 武器签名爆发 | 220–550ms | 机炮双曳光、电弧电冠、激光棱片、磁轨裂痕、点防雷达环、迫击炮冲击环 |
| 余辉稳定 | 550–900ms | 少量同色星尘沿武器朝向散开，塔身保持一圈低亮呼吸光后淡出 |

升星仪式可以使用金色星形轮廓表示稀有度，但武器签名爆发仍使用塔型冷色。这样既能读出“升到三星”，又不会把六种武器染成同一种金色烟花。

### 粒子性能与画面可读性预算

“震撼”依赖构图和时序，不等于无限增加活动粒子。建议按武器频率分配预算：

| 武器类别 | 每次开火建议新增自由粒子 | 单塔活动装饰上限 | 主要表现手段 |
| --- | ---: | ---: | --- |
| 高频：机炮、点防 | 0–4 | 20–28 | 弹尾、炮口环、命中时少量碎片；固定轮次强化 |
| 持续/中频：激光、电弧 | 4–10 | 28–40 | 复用持续光束、程序化折线和命中节点，不随 tick 重建整套效果 |
| 低频重武器：磁轨、迫击炮 | 16–32 | 48–64 | 单次大爆发、冲击环、吸入/喷出粒子和较长余波 |

全屏同时存在多个 3★ 时，建议按以下顺序降级：

1. 先减少远端余辉粒子和无伤害碎片。
2. 再减少第二、第三层冲击环的细节。
3. 永远保留真实弹道、真实 AoE 边界、主核心闪光和命中反馈。

环、光柱、尾迹和规则电丝优先用一次 `FxEvent` 内的程序化 `Graphics` 绘制；只有真正自由飞散、需要独立速度和寿命的碎片才进入粒子池。不要为了画三圈爆炸创建三十个事件对象。

### 推荐实施顺序

1. 先修复 2★ 机炮双弹扇开，并给 `Bullet` 增加出膛星级。
2. 让直射弹尾迹、命中事件、迫击炮落点都能读取正确的出膛星级。
3. 完成六种武器的 1★/2★/3★ 静态轮廓差异。
4. 优先制作 3★ 磁轨炮与 3★ 迫击炮，它们低频、收益最大，也最容易验证性能预算。
5. 再制作激光、电弧的持续效果，确保不会按伤害 tick 重复创建完整粒子组。
6. 最后制作机炮、点防的高频细节和全局粒子质量降级。

这套方案能让六把武器的三档发射读数都不同，同时保持当前伤害次数、弹药消耗、热量、充能和合成武器定位不变。3★ 的共同感受是“核心更亮、轮廓更大、余波更长”，但每把武器依靠自己的运动语言建立身份，而不是共用一套放大烟花。

## 实现注意事项

- 给 `Bullet` 增加“出膛星级快照”，与伤害、塔型、节流系一样在发射时定死，并纳入存档序列化；否则塔升星后，场上旧弹会突然换外观。
- 炮口偏移应属于发射几何，不应通过改变瞄准角制造。双管可以共享目标，但拥有不同出膛点。
- 视觉子弹、残影和碎片必须明确标记为不参与碰撞，不能混进真实弹丸池后意外增加伤害。
- 发射事件应直接携带星级，避免渲染层按 `towerType` 反查当前槽位。场上可能有同型不同星武器，反查会把低星开火画成高星效果。
- 迫击炮的爆炸事件应继承弹丸的出膛星级，而不是落地时读取当前武器星级。
- 高频武器的强化轮次必须使用固定计数或世界 tick 推导，不能用 `Math.random`；同一局回放时视觉节奏应稳定。
- 3★ 的震屏、顿帧和高亮闪光要分别服从设置中的震屏、顿帧与粒子质量开关。
- 同一个 `FxEvent` 应尽量绘制完整的多层环/光柱，避免为每一层装饰单独创建池对象。
- 为每种武器增加 1★/2★/3★ 发射快照测试，并为真实弹道增加命中与资源消耗测试。
