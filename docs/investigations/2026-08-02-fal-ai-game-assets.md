# fal.ai 游戏资源生成调研与首轮试制

- 日期：2026-08-02
- 项目：《星骸》STARWRECK
- 状态：首轮 MVP 覆盖完成，等待进入一致性迭代
- API 费用硬上限：**$25.00**
- 执行工具：`genmedia v0.7.0`

## 结论

fal.ai 适合参与《星骸》的美术生产，但应作为“视觉探索和静态素材生产工具”，不应直接替代全部战斗渲染。

最适合生成的内容：

- 敌人、炮塔、设施的概念图与单帧剪影；
- 升级卡面、图鉴插画和事件插画；
- 菜单背景、星区气氛图、商店页与宣传主视觉；
- 可被人工整理成贴图的金属、焊缝、虫壳等表面语言。

应继续程序化或人工规范化的内容：

- 任意扩建后仍需无缝连接的甲板和船体结构；
- 射界、弹道、爆炸、受击反馈等高频 VFX；
- 多方向、多帧且必须严格一致的动画；
- HUD、威胁罗盘和所有需要精确布局或本地化的文字。

原因不是单次生成费用，而是一致性成本。《星骸》的战斗可读性依赖冷色机械舰与暖色有机虫群的严格分离、俯视角和强剪影；这些约束必须通过固定 Prompt、调色和后处理统一。

## 项目资源规模

依据当前 GDD：

- M1：6 种炮塔、4 种支援、4 种敌人、1 个 Boss、1 个星区和基础船体/甲板表现；
- 1.0：10 种炮塔、8 种支援、8 种敌人、6 种塔进化、7 个船级外观、3 个 Boss 和 3 个星区；
- 战斗允许约 1000 敌人和 500 弹同屏，因此单帧轮廓与纹理图集比高帧数动画更符合当前技术结构。

预计 M1 需要 30–45 个独立静态成品；1.0 需要约 70–110 个，不含逐帧动画。

## 成本估算

可用成品的估算公式：

```text
成品成本 ≈ 候选生成次数 × 单次生成价
         + 定向修改次数 × 单次编辑价
         + 去背景、放大和废稿余量
```

| 阶段 | 估算 API 费用 |
|---|---:|
| 风格与流程验证 | $15–30 |

| 1.0 静态美术 | $300–700 |
| 强行使用 AI 生成大量动画帧 | $800–2,000+，不推荐 |

## 首轮试制目标

首轮不是把 $25 花完，而是在上限内回答以下问题：

1. 四种 MVP 敌人能否在 64–128px 尺寸保持可区分剪影；
2. 炮塔和支援设施能否共享拾荒焊接语言，同时让十种功能一眼可分；
3. 冷色机械与红紫暖色虫群能否在同一画面稳定分离；
4. 模型能否遵守严格俯视角、单主体、无文字、无阴影和干净背景；
5. 生成结果适合直接做静态贴图，还是只适合作为人工绘制参考。

### 试制范围

- 4 张美术方向探针：3 张 Recraft 设计板，1 张 FLUX 2 Pro 战斗气氛图；
- 4 种 MVP 敌人：蜂群蛭、侧掠者、尾随蛆、冲撞甲虫；
- 6 种 MVP 炮塔；
- 4 种 MVP 支援设施；
- 1–3 张船体/宣传方向图；
- 仅对通过初筛的结果进行追加变体和后处理。

## 视觉规范 v0.1

### 共同约束

- 固定正交俯视或近似正交俯视；
- 主体完整居中，四周留至少 12% 空白；
- 单主体，无文字、无数字、无徽标、无水印；
- 强剪影，64px 缩略图仍可辨认；
- 避免常规写实飞船、现代军武和干净科幻产品感；
- 材质强调废铁拼焊、外露铆钉、修补板和不对称结构。

### 我方机械

- 主色：深钢蓝、青蓝、冷白；
- 形状语言：矩形甲板、炮座、焊缝、外露结构；
- 允许少量琥珀警示灯，但不得进入敌方红紫主色域。

### 敌方虫群

- 主色：暗红、洋红、紫红和暖橙发光组织；
- 形状语言：甲壳、节肢、软体组织、非对称生物结构；
- 禁止蓝青主光，避免与玩家阵营混淆。

## 验收方法

每张候选按五项评分，每项 0–2 分：

1. 俯视角是否稳定；
2. 剪影是否符合功能；
3. 阵营色域是否正确；
4. 小尺寸是否可读；
5. 是否容易去背景、裁切并进入图集。

- 8–10 分：进入下一轮；
- 6–7 分：仅作概念参考；
- 0–5 分：停止在该方向继续消费。

## 首轮结果

### 模型路线结论

1. **FLUX 2 Pro 适合战斗单体。** 在每次只要求一个主体时，它能稳定遵守俯视角、完整构图、阵营色域和纯色背景；512×512 输出足够作为当前原型贴图源。
2. **Recraft V3 不适合直接批量生成战斗 Sprite。** 多对象设计板出现漏项、重复、普通地球昆虫、串色和构图裁切；单体也倾向卡面插画或海报构图。它仍可用于升级卡面、图鉴插画和矢量 UI 探索。
3. 纯色背景加本地色键移除可行。敌方使用 `#00ff00`，我方机械使用 `#ff00ff`；所有进入候选集的 PNG 均已生成 alpha 通道并验证透明角落。
4. 相同 Prompt 结构、材质词和色域约束已经产生较一致的系列感，暂时没有必要训练 LoRA。

## 游戏接入验证

第一版已接入 `src/render/renderer.ts`，运行时资源位于 `assets/game/fal-round-1/`：

- 4 种敌人继续使用原来的 4 个 `ParticleContainer`，没有拆掉千敌同屏的合批结构；
- 蜂群蛭保持静态旋转，另外 3 型按速度向量转向，冲锋前摇时改用已锁定方向；
- 6 种塔图跟随真实 `cell.turretOffset`，4 种设施固定在船体局部空间；
- 单张资源加载失败不会阻断开局，敌人回退程序化剪影，塔/设施回退原来的类型色块；
- 128×128 运行时图共约 324 KB，生产构建已确认 14 张均被 Vite 正确打包；
- 完整 Vitest：31 个文件、612 条用例全部通过；
- 无头 Chrome WebGL（Apple M3 Max）压测：1000 敌（691/164/93/52）场景读数约 110 fps，
  四型轮廓、甲板模块、射界与升级界面未见错位。该读数只用于回归比较，不等同于目标硬件基准。
