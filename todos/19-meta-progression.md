# 19 · 元进度解锁与图鉴

- 优先级:P2 — 给"再来一把"的理由;剪影快照底座已存在,解锁是纯增量
- 依赖:10(卡池)、14*(精英计数)、16*(星币,非阻塞);存档用 localStorage
- GDD 参考:§10 元进度(条件式解锁、图鉴收藏、无永久数值)

## 背景

评审结论:局内循环(战斗 → 升级 → 船坞)已完整,但**局与局之间没有任何连接**——
没有解锁、没有图鉴、没有"下一把的新理由"。GDD §10 的定位很明确:
"只解锁内容,不解锁数值"(新塔入池、新船体起手、新法令、新事件,全部条件式成就解锁),
拒绝永久属性加成。现有底座:结算界面已能抓船形剪影 dataURL(gameOver.ts 的
captureShipSilhouette)。本 issue 把"一局打完"变成"解锁了什么 + 图鉴多一条"的闭环。

## 任务

- [ ] 存档模块:`src/sim/progress.ts`(纯数据,可单测)或 ui 层;localStorage 读写
      解锁状态(失败局同样保存已达成条件,不惩罚尝试)
- [ ] 条件式解锁表:新建 `src/data/unlocks.ts`(条件 → 解锁项)。建议首批:
      - 首次胜利 → 解锁进阶塔入池(如导弹巢)
      - 单局击杀数达标 → 解锁新法令(与 18 联动)
      - 精英击杀计数(14)→ 解锁词缀更高的精英事件
      - 船形收藏:每局结算自动存剪影快照(底座已有)
- [ ] 卡池过滤:rollUpgradeOffer 的候选生成读解锁状态(未解锁的塔/法令不进池);
      注意与确定性口径的关系(解锁状态是存档的一部分,不改变同 seed 的 rng 序列
      —— 过滤在掷之前,和现有 offerLegal 同位置)
- [ ] 图鉴视图:结算界面或独立面板,展示已解锁/未解锁的塔、敌人、法令、船形剪影
      (灰显未解锁项)
- [ ] 解锁即提示:局内达成条件时弹 toast/结算页展示"解锁 XX"
- [ ] HUD/结算:显示已解锁计数与下一个解锁目标(可选,先做最小闭环)

## 验收标准

- [ ] 通关一次 → 存档写入 → 重开新局,解锁的塔确实出现在三选一池中
- [ ] 未解锁项在卡池中绝不出现(掷不中未解锁的塔)
- [ ] 失败局同样推进解锁计数(条件达成即记,不因失败回滚)
- [ ] 解锁状态改动不影响同 seed 的 rng 序列(过滤在掷之前,与 offerLegal 同位置)
- [ ] 船形剪影从第一局起就入图鉴(localStorage 存 dataURL,注意容量,剪影建议
      压缩/限量存储)

## 口径说明与交接

- **只解锁内容,不解锁数值(红线)**:解锁项全部是"进池 / 进事件 / 进图鉴",
  没有任何永久伤害/血量加成 —— 难度曲线保持诚实,每局强度全来自局内决策。
- **解锁 ≠ 存档 = 进度**:存档只存解锁布尔与剪影集合,不存局内状态
  (局内状态是 sim 的,不存在存档里)。
- **与确定性的关系**:解锁状态只收窄候选集合(少掷中未解锁项),不移动 rng 消耗
  次数 —— 与现有 offerLegal 的死卡过滤同一位置、同一口径,测试沿用。
- **容量注意**:每局剪影 dataURL 若 100KB 级,几十局就破 5MB localStorage 配额;
  存前压缩(降采样)或限制最近 N 张,别做"无上限收藏"。
