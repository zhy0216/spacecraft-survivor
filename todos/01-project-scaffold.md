# 01 · 项目脚手架与游戏主循环

- 优先级:P0
- 依赖:无
- GDD 参考:§13 技术方案、§16 风险(性能压测从 M0 开始)

## 背景

技术底座:TypeScript + PixiJS(WebGL)。性能预算(1000 敌 + 500 弹 @60fps)是 GDD 明确要求从第一天就压测的红线,不留到后期。

## 任务

- [ ] TypeScript + PixiJS 项目初始化(建议 Vite),`npm run dev` 可跑出画面
- [ ] 固定时步 60Hz 逻辑更新 + 渲染插值(逻辑与渲染帧解耦)
- [ ] 实体对象池:敌人 / 子弹 / 掉落物全部池化,运行期零 GC 抖动为目标
- [ ] 空间哈希碰撞查询(cell 尺寸 = 最大敌半径 × 2)
- [ ] 大批量渲染:敌人/弹幕用 ParticleContainer 或 instancing
- [ ] 种子化 RNG:全局唯一随机源,seed 可指定
- [ ] 常驻压测场景(debug 入口):生成 1000 敌 + 500 弹,显示 FPS/实体计数

## 验收标准

- [ ] 压测场景在中端核显达到 60fps
- [ ] 人为拖慢渲染(如 30fps 上限)时,模拟结果不变(固定时步生效)
- [ ] 同一 seed 两次运行,实体轨迹完全一致(确定性)
