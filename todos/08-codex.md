# 08 · 图鉴与内容资料

- 优先级：P1 — 内容翻译集中展示区，也是检查术语一致性的主入口
- 依赖：02、03
- 涉及：`ui/codex.ts`、内容 presenter、图鉴测试

## 任务

- [ ] 迁移图鉴标题、解锁统计、累计统计、返回、筛选标签和图片 alt 文案。
- [ ] 筛选状态使用稳定 key（all/weapons/enemies/edicts），显示标签才翻译；切换语言不改变当前筛选。
- [ ] 武器条目迁移：名称、节流系、射界、射程、DPS、星级成长、合成来源与变身说明。
- [ ] 敌人条目迁移：名称、行为短标签、HP/速度等资料、精英词缀名单、Boss 行为说明。
- [ ] 法令条目迁移：名称、作用域、非中性效果摘要、层数上限。
- [ ] 解锁条件迁移：首次胜利、单局击杀、累计精英击杀、无条件；数量使用插值/plural。
- [ ] 所有内容名称与词缀描述统一走 03 的 presenter，不在 codex 内维护第二套翻译或名称表。
- [ ] `edictSummaryText`、`behaviorName`、`unlockConditionText` 等展示函数接入 i18n，并保证未知行为/条件码显示编号。
- [ ] `refreshLocale()` 在图鉴打开时原地重画，保留：
      - 当前筛选
      - 滚动位置
      - hover/焦点尽量保持
      - 已解锁掩码和统计不变
- [ ] 迁移测试，不再用中文名称作为查找业务行的唯一身份；为行节点添加 `data-content-kind` / `data-content-id`。

## 术语要求

- [ ] 建立中英术语表并在资源中统一：weapon/tower、edict、affix、hull、scrap、star coin、refit、broadside 等。
- [ ] 产品最终选择“武器”还是“塔”作为玩家术语要统一；开发代码可以继续叫 tower，但同一语言的 UI 不得混用。
- [ ] “ammo / heat / charge” 三种节流系在升级卡、HUD、图鉴和法令中使用同一译名。

## 验收标准

- [ ] 中英文图鉴的条目数、解锁状态、配图和排序完全一致。
- [ ] 改内容翻译后，升级、商店、HUD、图鉴同时跟随，不存在第二份名称。
- [ ] 切换语言不重置筛选或滚动到顶部。
- [ ] 所有未知码都有本地化兜底并包含原始码。
- [ ] 图鉴测试覆盖武器、敌人、法令、锁定条件和合成来源的双语输出。

## 口径说明与交接

- 图鉴是翻译质量验收页：内容术语有冲突时优先在 presenter/resource 层解决，不在各业务页面打补丁。
- 图片本身若无文字无需按语言复制；alt/aria 文案必须翻译。
