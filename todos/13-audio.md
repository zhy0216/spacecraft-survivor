# 13 · 音频系统(WebAudio 合成器)

- 优先级:P0 — 全仓零音频,是当前爽感的最大缺口;成本低、收益立竿见影
- 依赖:—(完全独立,不碰 sim 的确定性口径)
- GDD 参考:§12「每条舷是一个声部,单舷多塔齐射时音效叠成和声——broadside 时刻要靠耳朵就能识别」

## 背景

评审结论:手感层(镜头顿挫、击杀爆点、威胁罗盘)已扎实,但全仓没有任何音频实现
(无 WebAudio 引用、无素材文件)。GDD §12 早在设计期就把"舷 = 声部、齐射 = 和声"写成了
音频方向的卖点,而今天一次漂亮的侧舷齐射只有视觉顿挫没有声音。
用 WebAudio 合成器(不依赖外部素材文件)半天可铺满,是"更好玩"性价比最高的一项。

## 任务

- [ ] 音频引擎封装:`src/render/audio.ts`(或独立 `src/audio/` 目录,不进 sim —— 铁律 1:
      sim 永不认识 DOM/WebAudio,音频只挂在渲染层与 main.ts 的事件出口上)
- [ ] 浏览器自动播放策略:首次用户输入(键盘/点击)时 resume AudioContext;提供静音开关
- [ ] 合成器基础:每类音效一个 short envelope(attack/decay),复用振荡器/增益节点,避免 GC 压力
- [ ] 开火音:按塔型/节流分色(弹药哒哒、过热持续嘶、充能爆发),音量压低不糊成一片
- [ ] 击杀音:短促爆点,音高随连杀/击杀密度轻微爬升(可选,先做基础版)
- [ ] 残骸拾取音:轻快高频叮声,与击杀音区分
- [ ] 受击音:低沉撞击 + 蹭甲板火花音(两种受击反馈 FXV_SPARK / FXV_HULL_HIT 已有区分,音频照同口径)
- [ ] 升级/时停音:三选一弹出与放置确认
- [ ] **broadside 专属和弦**:挂在渲染层已有的 broadside 反馈上(renderer.ts 的 broadsideTick
      触发点,world.broadsideCount ≥ 3 同帧)—— 齐射那一下叠出一个明显的和弦,这是本作的签名时刻
- [ ] 背景底噪层(可选,最后做):怪潮密度驱动的低音量底噪,音量随 WAVE_MAX_ALIVE 占比浮动

## 验收标准

- [ ] 无素材文件,全部合成器发声;打开即有声(需一次交互解锁,符合浏览器策略)
- [ ] 单舷 ≥3 塔齐射时能凭耳朵识别出与单塔开火不同的和弦(GDD §12 的验收)
- [ ] 击杀/拾取/受击三者在蜂群贴脸同屏时仍能区分(音色分域,不糊)
- [ ] 静音开关生效;关闭后零音频节点占用
- [ ] sim 侧零改动,`npm test` 全绿(确定性不受音频影响)

## 口径说明与交接

- **音频只消费渲染层/事件出口,绝不反向驱动 sim**:所有触发点都挂在现有回调或 FxEvent
  流上,不新增 sim → audio 的依赖,同 seed 确定性不受任何音频改动影响。
- **触发点清单**(实现时对照):塔开火(FXV_MUZZLE/BEAM/CHAIN/LANCE/BLAST)、击杀(FXV_KILL)、
  受击(FXV_SPARK/FXV_HULL_HIT)、broadside(renderer broadsideTick)、升级弹卡(ui/upgradeFlow)、
  放置/焊接(ui 回调)、残骸收取(sim/world drop collect)。
- **并发控制**:蜂群贴脸时一帧可能十几个受击事件,合成器要做"同类型音效限流/合并",
  否则瞬间超载变成刺耳爆音。
- **音量分级**:开火 < 击杀 < 受击 < broadside 和弦,主音量单旋钮(tweakpane 或 HUD 按钮)。
