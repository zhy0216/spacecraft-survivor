# 18 · 法令卡(全船被动)

- 优先级:P2 — 卡池多样性的便宜补充;权重缺口已注释,结构上是补齐 15% 的洞
- 依赖:10(经济/三选一池)
- GDD 参考:§7「法令:全船被动,不占格,占比刻意压低 15% —— build 主体必须长在甲板上,
  法令只是调味(P2 保护条款)」

## 背景

`sim/upgrade.ts` 的三选一池目前只有三类(塔 45 / 支援 25 / 甲板 15),代码注释明写
"法令仍归 M2;当前三类对应 GDD §7 的 45/25/15,缺席的法令权重不冒充空气卡"。
GDD 要求四类按 45/25/15/15。法令是**不占格的全船被动**——它恰好是甲板拼图
(P2:build 长在甲板上)之外的"调味层",实现成本低(读表生效),但给卡池带来
"这局火力流 / 这局转向流"的局内身份感。

## 任务

- [ ] 新建 `src/data/edicts.ts`:法令表(编号 → 效果),与 towers.ts 同风格纯数据。
      MVP 建议 4–6 条,全部数值型(不引入新机制):
      - 曳光协议:所有弹药系射速 +10%
      - 重心校准:转向 +10°/s
      - 磁力过载:拾取半径 +30%
      - 散热协议:过热上限 +20%
      - 结构加固:船体 HP +20
      - 巡航校准:巡航速度 +10%
- [ ] `sim/upgrade.ts` 候选池加第四类 OFFER_EDICT,权重 15(45/25/15/15 恢复 GDD 口径)
- [ ] World 持法令集合;效果生效挂在现读点(与 tuning 同口径:塔射速/转向/拾取半径/
      过热的 effective* 计算处现读法令,面板可热调)
- [ ] 法令不占格、不叠级(重复抽到 = 效果不叠加,或改为强化档,选一)
- [ ] UI:卡片展示法令名与效果;HUD 显示已生效法令图标(与支援连线同级的"所见即所得")
- [ ] 测试:同 seed 同操作,加入法令类别后序列与既有用例**兼容或显式更新**
      (类别数 3→4 会改 rng 消耗,见口径说明)

## 验收标准

- [ ] 法令生效可测:抽到"曳光协议"后弹药塔射速确实 +10%,面板读数变化
- [ ] 法令不占甲板格(放置流程无感知)、不参与邻接/射界判定
- [ ] 权重 45/25/15/15 下,卡池分布大体符合;卡面上绝不出"重复法令无效"的沉默陷阱
      (抽到已持有法令时要么叠档、要么候选生成时剔掉)
- [ ] 确定性:同 seed 同操作逐位可复现(更新既有 rng 消耗用例)

## 口径说明与交接

- **rng 消耗口径(全项目地基)**:`rollUpgradeOffer` 的消耗次数与类别数绑定
  (每候选位 2 次 rng,类别轮盘 3→4 类)。加法令必须**一次性改完并更新全部既有
  确定性用例**,绝不做"权重凑 85 归一化"的妥协 —— 注释里写的正是那条路:
  三类按 85 归一化是过渡态,补上法令就该恢复 100。
- **法令不进 checksum 的边界**:法令只改 effective 数值(射速/转向/HP 等),这些
  本就参与判定,所以法令集合本身**必须进 checksum**(与塔等级同口径),否则重放失配。
- **调味定位**:法令条数克制(≤6),效果全是数值,不引入新机制 —— 保护 P2
  "build 主体长在甲板上"。
