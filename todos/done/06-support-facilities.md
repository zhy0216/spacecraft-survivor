# 06 · 支援设施与邻接协同

- 优先级:P1
- 依赖:03, 05
- GDD 参考:§4.3 邻接协同、§5.3 支援设施

## 背景

支援设施对**正交相邻**格生效(不含斜角),效果连线所见即所得。注意:GDD §4.3 说 MVP 只实装弹药库、验证读得懂再加,§5.3 又标 4 种 ✅ —— 按 **4 种全做、弹药库先行**执行:先做弹药库+连线可视化并自测可读性,再补其余三种。

## 任务

- [x] 甲板上邻接效果连线/图标可视化(生效中的连线常显或悬停显示)
- [x] 4 种设施:

| 设施 | 效果 |
|---|---|

| 散热器 | 相邻过热系塔:过热上限 +50% |
| 电容组 | 相邻充能系塔:充能速度 +30% |

- [x] 节流类型不匹配时无效果(且 UI 不画连线,避免误导)

## 验收标准

- [x] 弹药库放在机炮旁,射速/装填变化可实测 —— 帧距 24 → 20 帧、装填 90 → 63 帧,有精确单测
- [x] 连线只出现在"真实生效"的配对上 —— 连线表与 buff 计算**读同一份** `supportLinks`,
      结构上不可能分裂;类型不匹配既不进 links 也不改数值,有单测
- [x] 装甲舱的 HP 加成随放置即时生效、拆除即时移除 —— `World.step` 帧首重刷 `ship.maxHp`,

## 口径说明与交接

- **叠加口径**:四个倍率一律**连乘**(两个弹药库夹一门机炮 = ×1.25² / ×0.7²),只有装甲舱的
  `hullHp` 是加法。连乘的理由与 damage.ts 那句"返回倍率而不是减伤值"同源:加法在四块围一门炮时
  会把装填时间推成负数。
- **buff 是缓存的派生量**:存在 DeckCell 的四个字段上,按 `deck.buffRevision !== deck.revision`
  重算一次(`syncSupportBuffs`),**不每帧扫四邻**。派生量不进 checksum,来源(`supportType`)进。
- **邻接判定唯一出口是 `neighborCell(deck, cell, edge)`** —— 正交四邻,斜角结构上进不来;
  洞与船体外同为 undefined,所以 12 号焊出非矩形甲板时自动吃同一条规则。
- **取值链路唯一**:塔的四个受影响读数一律走 `cellFireInterval / cellReload / cellHeatMax /
  cellChargeTime`(sim/tower.ts),它们内部才去乘 cell 上的缓存。别处不许再算第二份。
- **装甲舱不画连线**(它不作用于相邻塔),改画:盾形图标 + 沿它所护那一舷的内壁描一条冷白装甲带。
  舷线颜色**不能取 `def.tint`** —— 格填充已经是这个 tint,同色叠不透明同色底会合成回原色、
  整条线是零像素(本轮修掉的一个真问题)。
- **10(三选一)接手时**:`World.place(col, row, content, towerType, supportType)` 是唯一入口;
  支援设施本轮**不叠级**(往已占支援格再放同型仍是 `PLACE_TAKEN`),要不要给它加叠级由 10/后续决定。
