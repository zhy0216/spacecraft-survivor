# 06 · 三选一升级、升星与替换流程

- 优先级：P1 — 动态文案最多、状态组合复杂，单独实施与验收
- 依赖：02、03
- 涉及：`ui/upgradeFlow.ts`、升级 presenter、相关测试

## 背景

升级流程包含候选名称、数值描述、法令效果、拥有数量、三合一链式升星、变身名称、拒绝原因、
重摇、跳过和槽满替换。大量句子按中文语序在代码中拼装，不能只替换单个名词。

## 任务

- [ ] 拒绝原因从 `Record<number, 中文字符串>` 改为 `reason code → translation key + vars`，未知码保留原始编号。
- [ ] 卡片标题统一走 03 的 `towerName/edictName` presenter。
- [ ] 武器卡描述拆成可翻译的完整结构：射界、射程、表面 DPS、节流系玩法说明。
- [ ] 法令卡描述使用迁移后的 `edictDesc` presenter；倍率、百分比、秒、角速度走 locale formatter。
- [ ] 迁移等级/持有/合成文案：
      - 新武器从 1★ 起步
      - 已有各星级数量
      - 再来一把合成 2★
      - 连合到 3★
      - 变身为合成武器
      - 法令当前层 → 下一层 / 已满层
- [ ] 英文涉及数量时使用 `count` plural，不写 `1 weapons` 一类固定复数。
- [ ] 迁移升级标题、暂停提示、跳过手续费与返还、重摇价格、换槽标题、取消/返回提示、升星过场。
- [ ] 当前 `card.level.innerHTML` 不得接收完整翻译字符串。把主行/副行拆成真实 DOM 节点并分别用 `textContent`。
- [ ] `refreshLocale()` 在面板打开时重画当前候选、当前 world 持有数量、价格和 picker；不得重新 roll 候选或消费 rng。
- [ ] 切换语言时保留 phase：选卡/换槽/升星过场，不自动选卡、不关闭面板、不恢复战斗。
- [ ] 将纯文案函数改为接收 translator/presenter，或在测试前显式设置 locale；避免模块 import 时把某语言字符串缓存为常量。

## 验收标准

- [ ] 中英文下三选一展示的是同一组 `kind/type/level`，只改变文本。
- [ ] 切换语言前后 `world.offer`、rng cursor、星币、残骸和武器槽 checksum 不变。
- [ ] 槽满替换、重摇不足、法令满层、非法型号等所有原因码都有中英文文本。
- [ ] 合成链与变身文案在英文下语义正确，不依赖中文词序或量词。
- [ ] 翻译字符串不进入 `innerHTML`。
- [ ] upgradeFlow 纯函数与 DOM 测试覆盖两种语言和至少一条 plural 分支。

## 口径说明与交接

- 星星 `★`、DPS 等游戏符号可跨语言复用，但其周围句子必须整句翻译。
- UI presenter 可以读取 World 做展示快照，但不得修改 World 或调用任何会消费 rng 的方法。
