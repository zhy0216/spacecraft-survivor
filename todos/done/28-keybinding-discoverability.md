# 28 · I / Tab 键位可发现性

- 优先级:P2 — 两个核心玩法键(武器布局 / 射界叠加)目前在游戏里零提示,只活在代码注释与 GDD
- 依赖:无
- 来源:《玩法创新与改进探索》§七 #4;UI 旅程盘点"玩家发现不了的功能"

## 背景

I(武器布局面板)是槽位制的核心操作——换位是玩法不是调试工具(armoryPanel 文件头
明写,开发模式也建);Tab(按住看射界)是舷向游戏的关键读数。但 HUD 上唯一的键位提示
是加速条标签「加速 [空格]」(`src/ui/hud.ts:500`),I 和 Tab 在 HUD、暂停菜单、设置页
里**没有任何入口或文字**。盲测玩家会整局不知道能换位。

## 任务

- [ ] **HUD 常驻键位行**:左下角静音开关正上方加一行小字
      「[I] 武器布局 · [Tab] 射界」(muted 色、pointer-events 穿透、时停跟着整层淡出;
      对齐 48px 罗盘通道网格——`hud.ts:149/201` 注释里那套边距,别新开一档)。
      加速不重复进这行(它的条自带标签)
- [ ] **暂停菜单键位块**:`src/ui/pauseMenu.ts` 在设置按钮之前插一个静态键位表
      (非按钮,muted 小字):WASD 航向 / 空格 加速 / **I 武器布局** / **按住 Tab 射界** /
      Esc 暂停。暂停菜单本来就是玩家"我还能干什么"的求助页,键位放这里最顺
- [ ] **首局主动提示(可选,做不做由实施时定)**:首次进战斗 20s 内若从未按过 I,
      走解锁 toast 通道飘一条「按 I 可调整武器朝向」;"从未按过"标记落
      settingsStorage 旁的本地存储,**不进 sim、不进存档**
- [ ] 测试:hud.test 断言键位行存在与文案;pauseMenu.test 断言键位块;若做首局提示,
      钉"按过一次后永不再飘"

## 验收标准

- [ ] 不看任何文档的新玩家,从 HUD 或暂停菜单都能发现 I 与 Tab
- [ ] 键位行不遮罗盘通道、不接鼠标事件、时停时随 HUD 整层淡出
- [ ] `npm test` 全绿

## 口径说明与交接

- 纯 UI,零 sim、零 rng、零存档影响;`?debug` 形态同样显示(键位是玩法不是调试)。
- 设置页的「键位重绑」明确不做——单摇杆 + 四个功能键没有重绑需求,做了是伪需求面板。
- README 的操作说明小节顺手补一行 I/Tab 也行,但 README 全面修订归审计 P4(第二波外),
  本 issue 不背那口锅。
