# 11 · HUD 与威胁罗盘

- 优先级:P1
- 依赖:08, 09, 10
- GDD 参考:§11 UI/UX、§12 可读性规范

## 背景

威胁罗盘是舷向游戏的关键信息:玩家需要不看小地图就知道主压来自哪个方向、该把哪面舷转过去。战斗中甲板走简化渲染,细节留给时停放大视图。

## 任务

- [x] HUD 常驻元素:船体 HP 条、残骸/升级进度条、局内计时器、航段进度(替代 GDD 的星区进度)
- [x] **威胁罗盘**:屏幕边缘的主压方向箭头 + 强度表现(怪流密度→箭头粗细/亮度),常驻;数据来自 08 的出怪器实时统计
- [x] 战斗中甲板简化渲染:塔只显示色块 + 朝向 + 开火闪光;支援设施仅色块(细节在 Tab 射界视图与时停放置视图)
- [x] 升级三选一卡片 UI(名称/图标/一句话描述/当前等级)
- [x] 敌我配色落地检查:敌红紫暖色 / 船冷色,色盲模拟工具过一遍

## 验收标准

- [ ] 盲测口头验证:新玩家不看说明能指出"怪主要从哪边来" —— **必须由真人新玩家执行**;
      自动测试已钉住箭头位于来敌边缘且朝船内,独立复核确认语义与遮挡问题均已修复
- [x] 1000 敌同屏时 HUD 仍可读,无关键信息被遮挡 —— HUD 节点数恒定、不遍历敌池;
      独立浏览器复核在 1280×720 / 1000 敌下读数清晰,右侧为 Tweakpane 预留 288px
- [x] 全部 HUD 元素在时停放置态正确隐藏/淡出,不与放大甲板抢焦点 —— DOM HUD 统一淡到
      opacity 0.06;旧 Pixi HP 条已删除;冻结的炮口闪在放大与恢复缓动期间都不会压进放置视图

## 口径说明与交接

- **威胁实况不是脚本计划值**:`World` 对正式出怪器真正成功落地的事件做 1.25s 指数平滑;
  普通流与 burst 都计入,触及在场上限而丢弃的请求不计。方向无有效样本时才回落脚本方向。
- **HUD 是单实例 DOM 层**:HP、升级残骸、计时与航段每帧只改既有节点;重开只 `setWorld`,
  不重复 append 或注册监听器。根节点永久 `pointer-events:none`,暂停/结算统一淡出。
- **战斗 / 详细视图两档**:战斗仅留按型色块、炮口朝向与带冷白芯的开火闪光;
  Tab 或时停放大才显示射界、邻接连线、装甲与节流读数。暂停前的短效闪光不会在恢复缓动时复活错位。
- **升级卡片信息完整**:六塔与四支援各有独立图标、数据驱动的一句话描述与等级状态;
  支援设施明确写「设施不叠级 · 本次新建」,不再拿恒为 0 的 level 冒充「未装备」。
- **色盲审计检查真实像素**:敌色唯一来源是 `data/enemies.ts`;测试按敌纹理灰底 × tint 的实际合成色,
  经 protanopia / deuteranopia / tritanopia 三组矩阵后与全部我方实体保持 OKLab 距离 > 0.08,
  同时四种敌人仍有互异剪影作为非颜色通道。
