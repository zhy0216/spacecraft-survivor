# 08 · 波次脚本与单局地图

- 优先级:P1
- 依赖:02, 07
- GDD 参考:§6.3 波次语法、§9 局结构(裁剪为单地图)、§2.3(裁剪)

## 背景

MVP 的"一张地图"= 一个开阔太空战场 + 一串首尾相接的航段脚本,替代 GDD 的星图/节点结构。波次语法保留:`主压方向流(持续) + 侧压事件(定时)`,主压方向随航段缓慢旋转,让"最优舷"持续漂移。

## 任务

- [x] 波次脚本格式(JSON/TS 配置):每航段声明时长、主压方向起止角(如 0°→120°)、出怪流(种类/速率/随时间的密度曲线)、定时侧压事件(方向 + 怪组合)
- [x] 出怪器:在主压方向的屏幕外环形区生成,方向随脚本插值旋转
- [x] 精英插入接口预留(MVP 不实装精英)—— `WaveElite` 类型存在、每段 `elites: []`,无死代码路径
- [x] 单局结构:4 个航段脚本 × 每段 90–180s,总时长约 8–10 分钟 —— 实际 550s(9:10),方向共扫过 480°
- [x] 胜负流程:脚本走完 = 胜利结算;HP 归零 = 失败结算(联 09);结算界面显示存活时间/击杀数,一键重开
- [x] (可选)结算界面截取最终船形剪影 —— `renderer.captureShipSilhouette()`,抓 deckG 的 local bounds
- [x] 出怪使用全局种子 RNG(联 01),同 seed 同波次

## 验收标准

- [x] 主压方向的旋转能通过威胁罗盘读出(联 11)—— 本轮把 `world.threatDirection / threatIntensity`
      暴露出来并有单测钉住其随脚本插值旋转;**罗盘本体是 11 号的活**。
      「玩家被迫持续微调航向」**待真人试玩**
- [x] 同 seed 两局出怪序列一致 —— 跑真脚本 40s 逐只对比种类与出生位置
- [x] 一局从开始到胜利/失败/重开全流程无需刷新页面 —— `startRun(newWorld)` 换 World +
      `renderer.setWorld` + `placement.setWorld`;**真机重开第二局仍待人工过一遍**

## 口径说明与交接

- **压测模式没丢**:面板「运行」栏有 `stressSpawn` 开关,打开就整段旁路波次运行器、回到 01 号的
  定数出怪(本局因此没有胜利条件)。`tuning.stressEnemies` 与四条 `enemyMix*` 仅这条路生效。
- **出怪环以船为心**,半径 `SPAWN_RADIUS(1150) + rng × 150`。1150 是按 1440p 屏、船占屏高 20%
  反推的视野半对角(≈1084)加余量 —— sim 不知道屏幕大小,这个常量就是渲染层与 sim 之间的唯一约定。
  允许生在 `WORLD_RADIUS` 之外(那条边界只夹船,不是地图墙)。
- **rng 消耗顺序定死**:角(runner)→ 半径 → `initEnemy` 的 side,每只恰好 3 次、与型号无关。
  型号由脚本逐条流给死,不掷随机。
- **局终判定在 sim、流程在 main**:`World.settleOutcome()` 排在 step 最末(reap 之后,击杀数才入完账),
  失败优先于胜利,`onGameOver(result)` 一次性。World 自己不暂停、不重开、不动 loop。
- **重开换种子**(`seed + runIndex`)—— 面板那个按钮验不了「同 seed 可复现」,那件事得带 `?seed=` 刷新。
- **11(HUD)接手时**:罗盘直接读 `world.threatDirection`(弧度)与 `world.threatIntensity`(只/秒);
  航段进度读 `world.wave.segment` 与 `world.wave.segTime`。面板「波次(08)」栏已经把这四个数显示出来了。
