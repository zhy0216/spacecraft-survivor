# 07 · 整备商店与购买替换流程

- 优先级：P1 — 玩家决策核心，且当前含多处翻译字符串拼进 `innerHTML`
- 依赖：02、03
- 涉及：`ui/refitFlow.ts`、`shipDiagram.ts` 共用接口、相关测试

## 任务

- [ ] 迁移商店静态文案：眉题、标题、武器区、法令区、槽满 picker、取消、修复、刷新、完成整备、决战在即。
- [ ] 迁移购买结果与拒绝原因：售出、星币不足、满血、整备结束、无货、刷新不足等。
- [ ] 迁移动态预览：
      - 武器价格/折扣
      - 入手 1★
      - 槽满需替换
      - 与两把 1★ 合成无需替换
      - 连合/变身名称
      - 法令层数与单层效果
      - 修复比例与费用
- [ ] 武器、法令、波段名称统一走 03 的 presenter。
- [ ] 把货架卡、法令行、背包 readout 中的 `innerHTML` 字符串模板改成预建节点或安全 DOM builder：
      - 图片/图标节点单独管理
      - 名称用 `textContent`
      - 价格与折扣各自节点
      - 翻译资源不得包含 HTML 或 style
- [ ] `refreshLocale()` 重画当前货架与 pending buy picker，但必须保留：
      - 当前货架 type 与售出状态
      - 折扣位
      - pendingBuy
      - 舰船背包选择槽
      - 当前星币、HP 和是否可修复
- [ ] 语言切换不得调用刷新货架、购买、修复、完成整备等业务方法，不消费 rng、不扣币。
- [ ] 英文价格与数量句子使用插值/plural；星币符号 `★` 是否前置由翻译句子决定，不在代码里假定固定位置。
- [ ] 更新 DOM 测试：通过稳定 action/节点角色找卡片，不依赖中文文案定位；中英文分别验证关键状态。

## 验收标准

- [ ] 英文玩家可完成购买武器、槽满替换、买法令、修复、刷新、结束整备全流程。
- [ ] 切换语言前后货架、折扣、余额、HP、pendingBuy 和 rng cursor 完全一致。
- [ ] 无货/售出/未知型号保留可诊断信息，不显示裸翻译 key。
- [ ] `refitFlow.ts` 不再把翻译结果或内容名称插入 `innerHTML`。
- [ ] 窄屏下英文 picker 提示和按钮不遮挡舰船背包。

## 口径说明与交接

- “DOCK SUPPLY” 等英文装饰文字也进入资源；中文界面可以保留该英文眉题，但应由中文资源明确决定，而不是写死在 DOM。
- 刷新文案和刷新货架是两件事：前者纯展示，后者是消费行为，接口命名要避免混淆。
