# 05 · 武器塔框架与 6 种 MVP 塔

- 优先级:P0(其中机炮+电弧为 M0 灰盒最小子集)
- 依赖:03, 04
- GDD 参考:§5.1 塔属性框架、§5.2 武器塔、§5.4 塔升级、§14 数值初稿

## 背景

每座塔四要素:伤害 / 射程 / 弧度 / 节流机制。节流三选一(过热/弹药/充能)是支援设施(06)的作用锚点,必须做成三套可区分的机制。

## 任务

- [x] 塔基类/框架:属性配置化(单独数据文件,便于调参),索敌 = 射界内**最近优先**(§17.4 的 A/B 延后)
- [x] 节流机制 ×3:
  - **弹药**:弹夹 + 装填时间
  - **过热**:持续射击热量上升,过热强制冷却
  - **充能**:蓄力周期,满充放
- [x] 6 种塔(除机炮外数值占位):

| 塔 | 弧度 | 节流 | 行为 |
|---|---|---|---|
| 自动机炮 | 100° | 弹药 | 直射弹。**锚点数值**:6 伤 / 2.5 发/s / 射程 380 / 弹夹 20 / 装填 1.5s |
| 激光棱镜 | 60° | 过热 | 持续单体光束,融精英 |
| 电弧塔 | 150° | 过热 | 短程链式闪电,清蜂群 |
| 磁轨炮 | 30° | 充能 | 蓄力后直线穿透 |
| 点防阵列 | 150° | 弹药 | 近防速射;拦截弹幕接口预留(MVP 4 敌均无弹幕) |
| 等离子迫击炮 | 60° | 充能 | 抛射越过前排,落点 AoE |

- [x] 同名叠级 Lv1→Lv5:数值成长,原格生效不占新格
- [x] (可选)Lv3/Lv5 机制小跳变 —— 机炮 Lv3 双管(`burstAtLv3`)、Lv5 曳光弹(`pierceAtLv5`)

## 口径说明与交接

- **共享候选圈按"够得着的最远距离"取,不是按射程**(`towerOutreach`)。电弧塔的链能从射程边缘
  再往外走 (chainCount-1)×chainRange —— 按射程取圈会让 Lv5 的后几跳静默够不着,更糟的是会让
  这条链的长度取决于甲板上还有没有别的远程塔。已有回归测试钉住(退回修复即变红)。
- **光束存续 `FX_LIFE_BEAM` 必须 ≥ 激光的 `fireInterval`**,否则两次伤害 tick 之间没有光束在池里,
  "持续光束"会退化成 10Hz 频闪。已有不变量测试。
- **broadside 反馈实际几乎触发不到**:舷向归属取暴露掩码最低位,3×4 甲板下 BOW 3 / STARBOARD 3 /
  STERN 2 / PORT 2 —— 左舷与船尾结构上永远到不了「单舷 ≥3 塔同帧开火」。反馈本身接线正确,
  09 号做四舷判定时会换掉这套归属规则,届时这个可选项才真正可见。
- **06(支援设施)接手时**:三套节流的运行期字段互不相交(弹药只碰 `ammo/cooldown/reloadLeft`、
  过热只碰 `heat/coolLock/cooldown`、充能只碰 `charge`),有单测钉死 —— 三种设施各自的作用锚点
  是干净的。取值一律走 `towerXxx(def, level)` 这组函数,别直接读 `def.xxx`。
