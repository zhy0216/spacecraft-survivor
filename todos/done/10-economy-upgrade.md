# 10 · 残骸经济与三选一升级

- 优先级:P1(掉落+磁吸+"升级仅加塔等级"的最小版属于 M0 子集)
- 依赖:03, 05, 06
- GDD 参考:§2.2 分钟级循环、§7 经济与升级(裁剪)、§11 放置流、§14 数值初稿

## 背景

残骸 = 全程唯一成长资源。MVP 裁剪:无星币、无商店、无重摇、无法令、无甲板拼块(拼块见 12)。三选一池只剩武器塔(新塔或同名叠级)与支援设施。

## 任务

- [x] 残骸掉落物:敌人死亡掉落,对象池化;磁吸拾取(拾取半径参数化)
- [x] 升级曲线:所需残骸 = BASE × 1.25^级数;MVP 单局(~10 分钟)升级次数目标 12–15 次
      —— 25 分钟口径的 BASE=10 调整为本局长度适用的 BASE=35,形状仍锁定 1.25
- [x] 三选一生成:候选 = 新武器塔 / 已有塔同名叠级 / 支援设施;类别权重 65/35;
      候选不重复且必有合法格,甲板彻底放满时自动按跳过结算
- [x] 放置流(§11):三选一 → **时停** → 甲板放大 30%、合法格高亮 → 点击放置 → 恢复战斗
- [x] 时停期间模拟完全冻结(敌人、子弹、计时器、掉落全停)
- [x] 跳过按钮:返还 15 残骸;放置阶段 Esc / 右键 / 「重选」退回选卡且不扣费

## 验收标准

- [x] 时停冻结无泄漏 —— `FixedStepLoop.halt()` 当场丢弃本次补步余量,main 的 `run.paused`
      挡住后续 advance;整世界冻结用例逐项钉敌人/子弹/掉落/计时器与 checksum
- [x] 非法格不可确认放置;取消/跳过路径完整 —— UI 状态机 34 条 Node 用例覆盖
- [x] 一局能自然完成 12–15 次升级 —— `sim/economy.test.ts` 跑完 08 的 550s 真脚本,
      固定 seed 实测 **13 次**;真实塔火力/死亡/掉落/磁吸/候选/放置全链路,同 seed 最终经济与 checksum 一致
- [x] 拾取半径改动可体感验证 —— 面板「残骸经济(10)」提供起吸半径/速度/收取半径三根即时旋钮,
      世界级用例证明只改半径会按闭式收到更多残骸;**最终手感与千敌中的辨识度仍待真人试玩**

## 口径说明与交接

- **掉落是新实体**:`Drop` 进 `Pool`,维护 px/py,渲染走单独 ParticleContainer。每只敌人必掉一颗、
  面额按 `data/enemies.ts` 的 1/2/2/4,零 rng;在场上限 1200 是保险丝,触顶直接丢弃不留账。
- **磁吸单向锁定**:残骸进过起吸半径一次就不再松手,此后以固定速度直追船心;到站不冲过头。
  `magnetRadius(deck)` 是 12/后续磁力收集器 +30% 的唯一挂钩。
- **候选确定性**:每个候选位恒消耗两次 `world.rng`(类别 + 型号),类别回退不额外掷;
  `optionLegalCells` 直接复用 `canPlace`,所以卡片、合法高亮与最终确认读的是同一份规则。
- **World 只判经济、不管流程**:`offer/onUpgradeOffer/takeUpgrade/skipUpgrade` 在 sim;
  暂停、甲板放大、DOM 卡片与恢复战斗都在 main/ui/render。offer/upgrades/scrap 逐项进 checksum。
- **正式开局起手两门机炮**来自 `data/loadout.ts`,由 `applyStartingLoadout` 显式套用;
  不塞进 World 构造函数,保证规则单测仍能拿到全空甲板。
- **旧灰盒入口已删除**:`ui/placement.ts` 与它的 B/数字键绕经济放置口整个移除;
  纯函数拒绝文案迁到 `ui/upgradeFlow.ts`,重开的 `setWorld/syncHover` 接口保持不变。
