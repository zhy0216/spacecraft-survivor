# 12 · 甲板拼块扩建(延伸,可砍)

- 优先级:P2 — MVP 验证目标(转向手感 + 舷向火控 + 三选一循环)不依赖本条;若周期紧可整条推迟
- 依赖:03, 04, 10
- GDD 参考:§4.4 甲板扩建、§4.1(边缘内化)、§2.1(P3 船形即成长)

## 背景

扩建是 P3(船形即成长)的载体,也是"边缘内化"拼图张力的来源:焊接新块会把旧边缘格变成内部格,曾经的炮位变成内脏位。MVP 若做,只需最小闭环:拼块入池 → 焊接 → 射界/邻接重算。

## 任务

- [x] 甲板拼块卡入三选一池(权重占位 15%,恢复 GDD 池结构),形状:1×2 / L 形 / 2×2 / T 形
- [x] 焊接模式:时停;拼块吸附到船体任意外边缘,合法位置高亮;确认即焊死(局内不可拆、不可挪)
- [x] 焊接后全量重算:暴露边 → 边缘/内部格 → 射界(04)→ 邻接(06)
- [x] 边缘内化:被围死的武器塔进入离线态(灰显、不开火,03 已预留状态机)
- [x] 转向惩罚:每格 -1°/s(联 02 参数系统)
- [x] 受击判定体保持不变(09 已定);敌人蹭外圈甲板出火花不掉血
- [x] 船体渲染随占用格集合更新轮廓(带焊缝感的简单描边即可)

## 验收标准

- [x] 故意用 2×2 把一门在线塔围死 → 塔即时灰显停火;Tab 视图射界消失
- [x] 焊接后转向速率下降可测(数值面板)
- [x] 焊接后船形剪影明显变化(P3 的最小可见性)

## 口径说明与交接

- **扩容不移动旧船体**:甲板以稳定逻辑 `col/row` 和可扩 backing rectangle 存储;向船头/左舷
  焊接只扩 bounds、复用旧格对象,局部坐标仍以初始 3×4 为中心。L/T 的凹口保持为空气格。
- **焊接是原子拓扑变更**:四型拼块支持 90° 旋转;完整验证不重叠且与任一 occupied 格正交相邻后，
  才一次扩容/写入并全量重算 exposed、online、射界来源和邻接缓存。UI 与候选池都复用同一合法性。
- **边缘内化链路已自动验证**:2×2 围死左舷塔后，当帧 `exposed=0`、`online=false`、邻接加成撤销;
  塔循环与 Tab 射界都通过 `isTurretCell` 跳过离线塔，既有测试同时钉住节流冻结与不再开火。
- **成长代价与受击范围分离**:实际转向 = 基础值 − 新增 occupied 格数，面板逐帧显示;伤害核心仍固定为
  初始 3×4，扩建 occupied 格只参与擦碰火花，异形凹口不误判。
- **渲染证据**:revision 变化后底板只绘 occupied 格、逐格留缝并沿真实暴露边描轮廓;异形船头标识
  锚在真实最前暴露边。独立复核确认 7 项任务与 3 项验收均成立。当前环境没有浏览器截图回归，
  因此灰显强度、合法锚点密度与「剪影是否足够明显」仍建议下一次真人试玩顺手做最终美术体感确认。
